## 1. Background

### 1.1 The wider rewrite

`vroot` is mid-rewrite (`feat-rewrite-vroot`). The core interface moved from non-generic (`vroot.Fs`, `vroot.Rooted`, `vroot.Unrooted`) to **generics**:

```go
type Fs[F File] interface { Chmod(...); Open(name string) (F, error); ... }
type Root[F File, R Root[F, R]] interface {
    Fs[F]
    IsRoot()
    OpenRoot(name string) (R, error)
}
type File interface { /* ~*os.File minus syscall-specific bits */ }
```

The old `synthfs`, `memfs`, `overlayfs`, `osfs`, etc. were removed in `b1d69b8` and are being rebuilt against the generic core. `osfs` is the reference for the new conventions:

- `osfs.NewFs(path) (*Fs, error)` → `*Fs` implements `vroot.Fs[*os.File]` (escapable: blocks `..` in the path arg via `filepath.IsLocal`, but does not confine symlink targets).
- `osfs.NewRoot(path) (*Root, error)` → `*Root` implements `vroot.Root[*os.File, *Root]` (wraps `*os.Root`, fully confined).
- Helpers are generic: `vroot.ReadFile[F]`, `WriteFile[F]`, `ReadDir[F]`, `Sub[F]`.
- `vroot.FromIoFs(fs.ReadLinkFS, name) Fs[File]` (no rooted variant — `fs.FS` can't be confined). `vroot.ExpandFsFile(fs.File, name) File`.
- Read-only wrappers `vroot.ReadOnlyFs[F]`, `ReadOnlyRoot[F, R]`, `ReadOnlyFile`.
- Acceptance suite is generic: `acceptancetest.Setup[F, Fs]{Make}` + `RunFs`; `SetupRoot[F, R]{Make}` + `RunRoot`. `Make(t, lines)` builds a fresh fs pre-populated from `testhelper` setup lines.

### 1.2 What synthfs is

An **in-memory directory tree** whose **regular-file bytes are supplied by a `FileView`** — a pointer to content in some backing storage (in-memory buffer, a file inside an `fs.FS`, a byte range of another view, generated bytes…). It lets you assemble a tree that mixes heterogeneous sources without copying anything to disk.

Design intent (from the old README) — examples:

- Virtually split / concatenated files.
- Virtually compressed / decompressed files.
- Mixing files from different `fs.FS` instances into one directory; e.g. drop a generated hashsum file alongside imported content.

**Headline use case:** feed mixed/modified content to `tar.Writer.AddFS` / `zip.Writer.AddFS` (via `vroot.ToIoFs`) **without** staging to a temp directory.

`memfs` is just synthfs with the default in-memory allocator.

### 1.3 Why the old synthfs can't be ported verbatim

- It targeted the removed non-generic interfaces and the `Rooted`/`Unrooted` split.
- Its ingest API (`AddFile(name, view, dirPerm, filePerm)`, `AddFs(root, vrootFs, perm)`) was awkward — see §2 decision 6.

## 2. Decision log (settled)

| # | Decision | Choice | Rationale |
|---|----------|--------|-----------|
| 1 | Concrete file type | `vroot.File` | Sources are heterogeneous, so `*synthfs.Root` implements `vroot.Root[vroot.File, *Root]`. Same pattern `iofs_from.go` uses with `Fs[File]`. |
| 2 | Scope | **Root-only** | A pure in-mem fs has nothing "outside" to escape to, so the escapable `Fs` variant adds little. Smaller surface. `*Root` still satisfies `vroot.Fs[vroot.File]` via embedding, so the full Fs acceptance suite runs through `RunRoot`. |
| 3 | `FileView` shape | **Full handle**: `Open(flag) (vroot.File, error)` + `Stat()` + `Close()` | Maximum flexibility for sources that must own their handle (streaming, seek-only). `Stat()` added so the tree gets size/mode without opening. |
| 4 | Core type names | `FileView` / `FileViewAllocator` | Keep the established, explicit names. |
| 5 | Ingest method names | `AddFile` / `AddFS` | Idiomatic-cased revival (`AddFS`, not `AddFs`). |
| 6 | File mode on `AddFile` | **From the view** (`view.Stat().Mode()`) | The full-handle view already carries its own metadata, so no perm argument is needed — removes the old two-perm-arg (`dirPerm`,`filePerm`) wart. |
| 7 | Conflict resolution | **Per-entry callback** `AddFunc`; `nil` ⇒ merge dirs + overwrite | A resolver gives full per-entry control; the default keeps the common "merge several sources, last wins" path one call. |
| 8 | Parent-dir handling | Ingest **auto-creates** parents; interface methods **error** on missing parent | Required: acceptance suite asserts `Create`/`OpenFile`/`Mkdir` return `fs.ErrNotExist` on a missing parent and "must not create intermediate directories". `AddFile`/`AddFS` are synthfs-only (not interface) methods, so auto-create there is conflict-free. |
| 9 | `Option.MkdirPerm` | **Dropped**; scaffolding perm lives on the AddFS side | Parent-of-mount-point scaffolding perm is an ingest concern, not a filesystem-wide setting. AddFS uses an internal default (`0o755`, masked by `Umask`); source dirs keep their own `FileInfo.Mode()`; pre-`MkdirAll` + dir-merge (`AddDecisionKeep`) covers the rare override. |
| 10 | `AddFunc` error return | Returns `(AddDecision, error)`; non-nil error aborts the whole `AddFile`/`AddFS` and propagates as its return value | Lets resolvers fail-fast (e.g. `FailOnConflict`) and surface their own errors. Resolves OQ1. |
| 11 | `AddDecision` set | `AddDecisionSkip`(0) / `AddDecisionKeep` / `AddDecisionOverride`. `Merge` removed; `Ignore`+`SkipDir` collapsed into `AddDecisionSkip` | Once `AddDecisionKeep`-on-a-dir means merge, `Merge` is redundant. With it gone, `Ignore` and `SkipDir` always did the same thing (drop + don't descend), so they merge into one zero value. Resolves OQ2. |
| 12 | `AddFile` default (nil cb) | Same default resolver as `AddFS` (`MergeOverwrite`) → overwrites an existing leaf | One mental model for both ingest calls. Resolves OQ3. |

### Acceptance constraint captured (decision 8)


## 3. Open questions (need your call before coding)

- **OQ1 — `AddFunc` error return. ✅ RESOLVED:** `AddFunc` returns `(AddDecision, error)`; a non-nil error aborts the whole `AddFile`/`AddFS` and propagates as its return value. Enables a `FailOnConflict` resolver. (See decision 10.)
- **OQ2 — action set. ✅ RESOLVED:** `Merge` removed — `AddDecisionKeep` on a directory now means merge (reuse/create + descend). With `Merge` gone, `Ignore` and `SkipDir` were identical (drop + don't descend), so they collapse into a single zero-value `AddDecisionSkip`. Final set: `AddDecisionSkip`(0) / `AddDecisionKeep` / `AddDecisionOverride` (decision 11). *Shout if you'd rather keep `Ignore`/`SkipDir` separate.*
- **OQ3 — `AddFile` default (nil cb). ✅ RESOLVED:** Aligned with `AddFS` — both use the same default resolver (`MergeOverwrite`), so nil cb overwrites an existing leaf (decision 12).

### Resolved-but-confirm

- **Scaffolding parent perm** = `0o755` masked by `Umask` (proposed in chat, not explicitly confirmed). Switch to literal `0o755`?
- **memfs timing** — build the thin `memfs` wrapper in the same pass, or land `synthfs` first? (Default assumption: same pass, it's ~10 lines.)

## 4. Public API (consolidated)

### 4.1 Core type & constructor

```go
package synthfs // github.com/ngicks/go-fsys-helper/vroot/synthfs

type Root struct{ /* shared in-mem tree + resolved Option */ }

var _ vroot.Root[vroot.File, *Root] = (*Root)(nil)

// NewRoot builds an empty synthetic filesystem. name is reported by Name().
// opt nil ⇒ all defaults (incl. in-memory allocator).
func NewRoot(name string, opt *Option) *Root

type Option struct {
    Clock         clock.WallClock               // nil → clock.RealWallClock()
    Allocator     FileViewAllocator             // nil → in-mem; used by Create / OpenFile(O_CREATE)
    Umask         *fs.FileMode                  // nil → 0o022; applies to Create/Mkdir (and scaffolding), NOT to AddFile views
    MaskChmodMode func(fs.FileMode) fs.FileMode // nil → mask to fs.ModePerm; use fsutil.MaskChmodMode for OS emulation
    DisableOpenFileRemoval bool                 // true → Remove on an open file errors (windows-like ERROR_SHARING_VIOLATION)
}
```

`*Root` implements every `vroot.Root[vroot.File, *Root]` method (`Chmod`, `Chown`, `Chtimes`, `Close`, `Create`, `Lchown`, `Link`, `Lstat`, `Mkdir`, `MkdirAll`, `Name`, `Open`, `OpenFile`, `OpenRoot`, `ReadLink`, `Remove`, `RemoveAll`, `Rename`, `Stat`, `Symlink`, `IsRoot`). `OpenRoot` returns a `*Root` sharing the same subtree, confined to it.

### 4.2 Backing content

```go
type FileView interface {
    // Open returns a fresh handle each call (offset etc. are per-handle). flag is
    // os.OpenFile-style; the view may reject write flags with errdef.EROFS.
    Open(flag int) (vroot.File, error)
    // Stat reports current metadata. The tree treats Size as authoritative (live);
    // mode/mtime seed the node at bind time, then are owned by the node.
    Stat() (fs.FileInfo, error)
    // Close is called when the view is unlinked from the tree (removed / renamed over).
    Close() error
}

type FileViewAllocator interface {
    // Allocate creates a fresh, writable view for a newly created file.
    Allocate(name string, perm fs.FileMode) (FileView, error)
}
```

Built-ins:

```go
func NewMemAllocator(c clock.WallClock) FileViewAllocator        // default allocator (writable, in-mem)
func NewBytesView(b []byte, mode fs.FileMode, mt time.Time) FileView // read-only over []byte
func NewFsView(fsys fs.FS, name string) (FileView, error)        // read-only, backed by an fs.FS file
func NewRangedView(v FileView, off, n int64) (FileView, error)   // read-only byte-range slice of another view
```

(Possible later additions, not in scope now: `NewConcatView(...FileView)` for virtual concatenation; a vroot-backed view.)

### 4.3 Ingest

```go
// AddFile binds view as a regular file at name (mode from view.Stat()). Missing
// parents are auto-created. cb nil ⇒ default resolver (same as AddFS:
// MergeOverwrite — an existing leaf at name is overwritten).
func (r *Root) AddFile(name string, view FileView, cb AddFunc) error

// AddFS eagerly walks fsys (depth-first, parents before children) and binds a
// read-only view for each regular file, recreating directories. If fsys also
// implements fs.ReadLinkFS, symlinks are reproduced. Missing parents of name are
// auto-created. cb nil ⇒ default resolver.
func (r *Root) AddFS(name string, fsys fs.FS, cb AddFunc) error
```

I/O and structural failures are returned directly by `AddFile`/`AddFS`. The callback chooses *policy* and may also abort by returning a non-nil error, which becomes the operation's return value.

```go
// AddFunc is called once per incoming SOURCE entry (scaffolding parents of the
// mount point are NOT surfaced — they are internal plumbing). incoming is never
// nil; existing is the entry already at that path, or nil if the path is free.
// A non-nil error aborts the whole AddFile/AddFS and propagates as its return
// value. nil AddFunc behaves as MergeOverwrite.
type AddFunc func(incoming, existing AddEntry) (AddDecision, error)

type AddEntry interface {
    Path() string      // slash path within the synth tree where the entry lands
    Info() fs.FileInfo // pre-resolved metadata (mode/size/mtime)
}

type AddDecision int
const (
    // AddDecisionSkip (zero) drops the incoming entry; for a directory its whole
    // subtree is pruned (children not visited). Any existing entry is untouched.
    AddDecisionSkip AddDecision = iota
    // AddDecisionKeep prefers the existing entry. For a directory it MERGES: the
    // directory is reused (created if absent) and the source's children are
    // visited so they combine with it. For a non-directory the existing leaf is
    // kept and incoming dropped (with no existing entry, incoming is not added).
    AddDecisionKeep
    // AddDecisionOverride replaces whatever is at the path with the incoming
    // entry. For a directory, the source's children are placed under the fresh dir.
    AddDecisionOverride
)

// built-in resolvers
func MergeOverwrite(incoming, existing AddEntry) (AddDecision, error) // nil default: dirs merge, leaves overwrite
func MergeKeep(incoming, existing AddEntry) (AddDecision, error)      // first-source-wins (keep existing leaf)
func FailOnConflict(incoming, existing AddEntry) (AddDecision, error) // dirs merge; error if a leaf already exists
```

## 5. Ingest semantics

`AddDecision` resolution (incoming entry vs. what already occupies the path):

| AddDecision | existing node | this node | descend (incoming dir) |
|-----------|---------------|-----------|-------------------------|
| `AddDecisionSkip` (0) | untouched | incoming dropped | no (subtree pruned) |
| `AddDecisionKeep` | dir: reused; file: kept | dir: ensured present; file: incoming dropped | yes (children merge in) |
| `AddDecisionOverride` | replaced | becomes incoming | yes (into fresh dir) |

Worked example — mixing two sources + a generated file:

```go
r := synthfs.NewRoot("synth://", nil)
r.AddFS("pkg", embedA, nil)                                   // source A under pkg/
r.AddFS("pkg", embedB, nil)                                   // source B merges into pkg/ (default merge+overwrite)
r.AddFile("pkg/SHA256SUMS", synthfs.NewBytesView(sum, 0o644, now), nil) // generated, alongside
tw := tar.NewWriter(w)
tw.AddFS(vroot.ToIoFs[vroot.File](r))                          // → tar, no temp dir
```

## 6. Permission rules

- **`Create` / `OpenFile(O_CREATE)`**: node mode = `perm &^ Umask` (os-like); content via `Allocator.Allocate`.
- **`Mkdir`**: node mode = `perm &^ Umask`.
- **`AddFile`**: node mode = `view.Stat().Mode()` **verbatim** (umask not applied — bound content keeps its source perms).
- **`AddFS`**: each source dir/file keeps its own `FileInfo.Mode()` verbatim.
- **Scaffolding parents** (intermediate dirs of an ingest mount point, with no source): `0o755 &^ Umask` (see §3 confirm). Source dirs that merge into a pre-created dir keep the pre-created dir's mode (`AddDecisionKeep`).
- **`Chmod`** mutates node mode through `MaskChmodMode` (default = mask to `fs.ModePerm`; OS emulation via `fsutil.MaskChmodMode`).

## 8. Test plan

- **Acceptance:** `acceptancetest.RunRoot(t, acceptancetest.SetupRoot[vroot.File, *synthfs.Root]{Make: func(t, lines) *synthfs.Root { r := synthfs.NewRoot("synth://", nil); testhelper.New[*testing.T, vroot.File](t, r).SetupLines(lines...); return r }, Option: …})`. `RunRoot` already includes the full `Fs` suite + `OpenRoot` + escapes + race.
  - `Option`: `Os` left as env (auto-detect). Symlinks supported. Chown is stored (no real ownership) → set `ChownUid`/`ChownGid` to small values; `SkipChown` likely false. Confirm Seek/ReadAt/WriteAt all supported (in-mem view supports them) → no Skip flags expected.
- **Ingest (`add_test.go`):** bytes/fs/ranged views; `AddFS` merging two `fs.FS` into one dir; `AddDecisionOverride` / `AddDecisionKeep` / `AddDecisionSkip` / custom resolver + `FailOnConflict` error path; parent auto-create; `AddFile` mode-from-view; symlink reproduction when source is `fs.ReadLinkFS`.
- **fs.FS conformance:** `fstest.TestFS(vroot.ToIoFs[vroot.File](r), …)` over a populated tree.
- `go test ./...` and `go test -race ./...`.

## 9. Implementation phases

1. Scaffold package; `tree.go` + `node.go` + `stat.go` (ported & de-duplicated from old synthfs), with rooted symlink/`..` confinement.
2. `view.go` + built-ins (`view_mem.go`, `view_bytes.go`, `view_fs.go`).
3. `handle.go` — stateful file/dir handles over a `FileView` (offset, flags, append, mtime bump, `ReadDir` cursor).
4. `root.go` + `option.go` — `Root`, `NewRoot`, all `vroot.Root` methods, `OpenRoot`.
5. `add.go` — `AddFile`, `AddFS`, resolver callback + built-ins.
6. `memfs` wrapper.
7. Tests: acceptance + ingest + race.
8. Update the `vroot` README synthfs section to the generic API (currently documents the removed pre-generics API).
